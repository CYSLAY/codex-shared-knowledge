# Design Director

Optimize for the best finished result, not the fewest skill calls. Select every complementary skill that materially improves the target effect, but give each skill a distinct responsibility and avoid duplicated ownership.

## Start with the outcome

Build a compact task card before production:

- deliverable: website/UI, presentation, image, video, or cross-media;
- target effect: what the audience should perceive, feel, or accomplish;
- quality mode: finished work by default; shorten only when the user asks for a quick draft;
- hard constraints: brand, dimensions, stack, editability, prohibited methods, deadline, and permissions;
- acceptance method: live test, rendered pages, file inspection, or complete playback.

When creative direction or behavior is not already settled, use `brainstorming` before implementation and honor its approval gate. When the request is already an approved design or a deterministic mechanical change, do not reopen settled decisions.

## Route capabilities by responsibility

Choose one lead workgroup, then add the specialist capabilities required to reach the target effect. Read [references/workgroups.md](references/workgroups.md) only for the deliverable types involved.

Classify candidates as:

- **required**: omission would materially weaken the intended result;
- **conditional**: activate only when its trigger is present;
- **prohibited**: conflicts with a user constraint or the selected production method.

Do not skip an applicable specialist merely because general capability could approximate it. Do not stack skills whose only contribution is to reconsider the same design decision.

Before production, state the target effect and intended skill chain in one concise update. This is a transparent execution notice, not a request for per-skill confirmation.

## Resolve conflicts

Use this precedence:

1. explicit user requirement;
2. target effect and acceptance criteria;
3. existing project design system and technical constraints;
4. lead skill's overall direction;
5. specialist skill's local recommendation;
6. generic convention.

Specialists enhance the lead direction; they do not silently replace it. Prefer comprehension, operability, accessibility, and performance over decorative motion. If a selected skill is unavailable, use an installed equivalent; otherwise use a disclosed general-capability fallback without claiming that the missing skill ran.

## Finish with one acceptance pass

Judge the observable deliverable, not whether the planned skills were called:

1. target effect achieved;
2. content and visuals accurate and complete;
3. applicable interaction, motion, or playback works;
4. rendered, exported, or live result has no obvious defect.

Include responsive, performance, accessibility, or format-specific checks only when relevant. If the result fails, return to the responsible stage, correct it once automatically, and recheck. Escalate only a remaining material issue or a choice that changes brand, business meaning, authorization, or an irreversible action.
