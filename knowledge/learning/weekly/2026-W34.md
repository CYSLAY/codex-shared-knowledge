## 合并后的认识

1. 资料型演示文稿的稳定主线是“来源证据 → 多条故事线与 SCR → 逐页内容/密度计划 → 视觉方向或蓝图 → 可编辑文件 → 渲染与真实软件验收”。CyberPPT 与 PPT-Master 提供了独立支持，C-019 由中提高为高。
2. “可编辑”和“看起来像蓝图”不能互相替代。复杂视觉可以分层保真，但标题、正文、关键数字、简单图表、表格和结论条必须有明确的原生编辑策略；蓝图不能整页铺成最终背景。
3. 设计、编码、视频和知识路由的共同规律不是堆工具，而是先判定任务阶段，再调用职责互补的能力并把输出交给下一阶段验收。发现、已读、已安装、可调用和已验证必须分开记录。
4. 文档转 Markdown、源码模板、Stitch、镜头配方和薄路由都属于中间层能力：它们改善输入或交接，但不能替代原格式、许可、隐私、业务逻辑和最终成品验收。
5. 本周多个来源再次支持“事实与视觉分离”：ImageGen、科研图和页面蓝图中的文字、数据、因果或图表值不能自动成为事实，必须回到源材料或明确标记缺口。

## 冲突、失效与待验证

- 视频中的热度、Token 降幅、成本和“还原度”会随时间、模型和材料变化，不作为稳定能力指标。Ponytail 的“Token 暴降 90%”已由官方基准纠正；CyberPPT 的“4 亿 Token”和“超出预期”保留为作者体验陈述。
- 两条科研绘图展示仍没有可唯一核验的同一官方产品身份，不能合并为一个已验证工具，也不能提高其输出、隐私或可编辑性置信度。
- Stitch MCP 属于外部 Beta 服务，来源机器未配置；敏感资料上传和认证仍需单独授权与数据边界检查。
- `image-to-code`、Ponytail、Table-GitHub-Capability-Router 与 CyberPPT 仅已读官方资料或学习方法，来源机器未安装；接收者机器必须重新检查，不能直接声称已调用。
