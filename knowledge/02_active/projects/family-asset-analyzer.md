# 家庭资产分析工具

## 项目目标

面向顾问与家庭用户的资产负债、现金流、教育目标和结构健康分析工具。产品输出是“结构提醒与行动顺序”，不是贷款审批、投资决策或个性化金融建议。

## 核心架构

- React + TypeScript + Vite；Zod、Zustand、IndexedDB、ECharts。
- 本地 IndexedDB 是第一数据源，Supabase 只承担显式同步和多设备读取。
- 客户使用 UUID；资产、负债、收入、支出、家庭成员和教育目标保持结构化。
- 提供 PWA、离线访问、打印/PDF、加密备份和响应式界面。

## 分析模型

- 所有现金流先统一成年化口径；年度结余扣除生活支出与债务还款。
- 应急资金只计算可随时使用、非长期锁定且明确标注为可应急的资产。
- 必要月支出包含必要生活支出和债务月供。
- 健康分析覆盖净资产、杠杆、固定资产集中度、短期偿债覆盖、债务偿付、应急月数、结余率、收入集中度、长期投入和教育准备度。
- 指标门槛是产品提醒线，不冒充统一行业标准；空白数据返回“待补充”，不把缺失值误判为零。
- 任何关键指标进入严重风险状态时，总分最高限制为 49，避免平均分掩盖负净资产、短期流动性不足或现金流赤字。
- 长期现金流计划支持收入与支出增长率、起止年份、逐年覆盖和有无收益率两条余额轨迹。

## 数据安全与发布纪律

- 浏览器只使用 Supabase Project URL 与 Publishable key；安全边界来自 RLS、grant 和受控 RPC，不来自“隐藏前端 key”。
- 云同步不等于应用层端到端加密；涉及受监管或高度敏感数据时，需要另行评估字段加密、审计、备份和合规。
- 数据结构升级只能增量迁移，不清库、不批量覆盖、不因部署重写业务字段。
- 删除必须由用户显式触发、二次确认，并同时区分本地与云端结果。
- 前端发布和数据库迁移是两条独立流程；不能假设推送网页会自动执行迁移。
- 发布前必须完成测试、构建、跨尺寸关键路径、真实双设备同步、RLS/权限复核和密钥泄漏检查。

## 可复用经验

1. 决策型指标应同时输出数值、公式、解释、行动和参考口径，而不是只给分数。
2. 缺失数据必须显式建模为“未知”；在高风险业务里，“未知=0”会制造虚假确定性。
3. 综合评分需要设置硬性风险上限，否则平均算法会掩盖单点致命风险。
4. 本地优先产品要把“保存”“同步”“备份”“删除”设计成不同动作和状态。
5. 发布验收必须覆盖数据库权限与真实设备数据流，不能只以构建成功作为完成标准。

## 当前边界

- 6 位密码只适合受控使用范围；扩大用户规模时需升级认证、限流和审计。
- 教育费用内置值属于可更新的估算基准，应显示来源与时间，不应作为确定报价。
