# Codex 知识工作流与外部记忆

## 当前认识

所谓“永久记忆”更适合实现为可维护的外部文件系统，而不是要求模型无限保留聊天上下文。有效的系统应同时解决写入、索引、按需读取、压缩和复盘五个环节。

## 推荐结构

- 稳定层：用户明确确认的规则、偏好和长期信息。
- 活跃层：进行中的项目、主题摘要、重要决策和最近变化。
- 归档层：原始来源、历史记录和低频资料。

## 最小上下文策略

任务开始时只读取总索引、相关主题或项目摘要及最近更新。需要证据时再沿链接打开原始资料，避免一次性加载整个知识库。

### 薄路由层

- 只存储分层还不足以让 AI 自动使用知识；需要简短路由表把日常任务语义映射到相关页面。
- 路由入口保持薄、可截断安全：用途、禁用条件和当前状态优先出现，命中后只读 Top-1 或最多 1—3 个相关页。
- 知识路由回答“这项任务查哪页”；能力路由回答“这项任务用哪个 Skill、Plugin、MCP 或 CLI”。两者可以共享语义识别原则，但不混成无边界大目录。
- 失败反馈应变成可验证的路由改进；只在重复出现、用户确认或实战验证后提升为稳定规则。

### 能力生命周期

- 发现、读说明、安装、启用、自动调用和全局部署是不同状态，不得因为项目“已入库”就跳过健康、权限、风险、范围与回滚门。
- 能力查找始终保留“不使用额外工具”作为候选；只有额外能力对当前任务有明确增量时才进一步读取或请求安装。
- 参考实现：<https://github.com/duoduoler-ops/Table-GitHub-Capability-Router>。其公开版本提供 schema、薄发现表、语义命中表、能力 manifest、事务写回和校验；接收者是否安装必须在运行时检查。

## 任务触发与应用协议

1. 先识别任务的目标、交付物、领域、风险和所需能力，不依赖精确关键词。
2. 从总索引选择最相关的 1—3 个主题或项目页面。
3. 将命中的知识转化为当前任务的设计决定、工程约束、工作流、检查单和验收标准，而不是只在回答中提到来源。
4. 多领域任务可以组合知识；无关内容不读取。
5. 当前任务的明确指令高于历史经验；低置信度候选不得当作确定事实。

### Skill 与知识的边界

- 视频中提炼出的思路、框架和验收方法，只要与任务相关，就可以作为知识直接应用。
- 可执行 Skill 必须实际存在于当前可用技能列表，并先读取其说明后才能调用。
- 视频或网页明确给出 Skill 名称时，该名称会触发一次“Skill 学习”：优先查找作者或官方发布的说明、公开仓库、`SKILL.md`、安装页和示例，提炼其触发条件、工作流、输入输出、依赖、限制与验收标准。
- Skill 学习不要求安装。未安装时仍应把有依据的方法转化为任务约束和检查单，但不能假装已经调用；当前机器实际可用时，必须先读取当前版本说明再调用。
- 只有技能名称或效果演示、没有公开说明时，应保留信息边界并登记待补资料，不根据宣传效果臆造实现流程。
- 实际项目验证过的知识优先级高于单一视频观点，但仍需服从当前任务和最新事实。

### Skill 学习记录的最小字段

1. Skill 名称、作者、版本或发布日期。
2. 原始发布页、官方文档、仓库或 `SKILL.md` 来源。
3. 触发场景与不适用场景。
4. 输入、输出与核心步骤。
5. 所需工具、依赖、账号和权限。
6. 可编辑性、可复现性、安全与交付验收。
7. 当前状态：仅听说、已读说明、已安装、已验证或已淘汰。

## 自动维护

- 每次采集后更新来源笔记、候选洞见和相关主题。
- 定期合并重复观点并保留冲突。
- 用户确认、实践验证或多来源支持后，才能提高观点可信度。
- 实际任务应用后，把成功、失败和适用边界反馈到相关主题或候选洞见，形成验证闭环。
