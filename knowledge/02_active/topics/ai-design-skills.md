# AI 设计语言与 Skill 化

## 当前认识

高质量网页复刻的关键不是只模仿截图外形，而是把设计规则结构化，使其能够迁移到新页面和新产品。

## 五层分析框架

1. 版面：容器、网格、对齐、层级和响应式关系。
2. 字体：字号阶梯、字重、行高和文字层级。
3. 颜色：背景、前景、强调色、对比度和状态色。
4. 动效：触发条件、时长、缓动、节奏和空间关系。
5. 留白：区块间距、密度、呼吸感和视觉节奏。

## 可复用原则

- 先形成设计语言说明书，再生成页面。
- 评价结果时同时检查层级、节奏、留白、字体关系和动效逻辑。
- 真正可迁移的产物是规则或 Skill，而不是单个复刻页面。
- 效果演示只能证明能力边界；若要沉淀为可复用方法，还应记录工具、输入、框架环境、时间线、触发与清理、性能约束和交付格式。
- 五层设计语言来自单一完整视频，适合作为中等置信度的分析框架；具体数值（如强调色比例、动效位移和留白尺度）只属于该示例，不能机械套用到所有项目。
- 截图适合传递外观，源码或可运行模板更适合传递交互逻辑、响应式关系与细节；前提是来源和许可清晰。
- 前端 Skill 要按阶段路由：设计方向、既有界面审查、参考图实现是三个不同任务，不能因为都和“做网页”有关就混用。

## 前端 Skill 路由

| 任务 | 优先能力 | 触发条件 | 不适用 | 当前状态 |
|---|---|---|---|---|
| 落地页、作品集、品牌页或重设计 | `design-taste-frontend` | 需要先确定受众、设计语言、视觉变化度和动效强度 | 密集后台、数据表格、纯逻辑修复 | 调用前检查当前机器是否已安装，并读取实际版本说明 |
| 现有 UI 上线前审查 | `web-design-guidelines` | 已有代码文件，需要检查层级、状态、一致性和可访问性 | 尚未形成界面或需要从零设计 | 官方 Skill 已核验；调用前检查当前机器可用状态 |
| 明确截图/设计稿到可交互前端 | `image-to-code` | 视觉目标唯一明确，能够做同视口浏览器 QA | 只有文字需求、目标不明确或希望自由重设计 | OpenAI 官方 Skill 已核验；调用前检查当前机器可用状态 |
| 复杂交互的高完成度起点 | 合法源码模板 + AI 适配 | 模板许可清楚，需要保留动效、响应式与组件状态 | 许可不清、原创品牌或复杂业务流程 | 只沉淀方法；`yuanpu.cc` 官方条款未核验 |
| PRD 到可视原型再到实现 | Google Stitch + 官方 MCP/导出 | 已明确页面与模块，但需要先探索视觉方案并把稳定原型交给编码代理 | 只修逻辑 Bug、已有完整设计稿、不能上传内容到外部服务 | Stitch MCP 官方 Beta 已核验；调用前检查当前账号、配置与权限 |

## 设计与工程分层工作流

- 前端目标应同时包含视觉方向与页面/模块/状态/数据需求；只有其中一项容易导致“好看但不能用”或“能用但同质化”。
- 可采用“设计约束 → Markdown PRD → 可视原型 → 设计资产交接 → 交互与业务实现 → 浏览器 QA”的阶段流程。
- Stitch 可作为原型层，但不是必选工具。当前环境若已有 `design-taste-frontend`，可直接完成设计方向与前端实现；只有需要多版可视探索或跨工具交接时才考虑 Stitch。
- MCP 认证信息属于敏感配置。任何 API Key、访问令牌或视频画面中的密钥都不得进入知识库、PRD、提示词档案或版本库。

## GSAP Skills 适用规则

- 官方仓库 `greensock/gsap-skills` 已核验，覆盖 core、timeline、ScrollTrigger、plugins、utils、React、性能和框架集成。
- 当任务需要复杂时间线、滚动驱动动画或跨框架动画时可优先考虑；简单 CSS 过渡或项目已明确选用其他库时不强行替换。
- GSAP Skills 的可用状态应在任务开始时检查；未安装时只能应用已沉淀的方法，不能声称实际调用。需要执行时再安装并读取对应 `SKILL.md`。

## Emil Kowalski 设计工程 Skills

- 官方仓库：<https://github.com/emilkowalski/skills>。`apple-design` 把 Apple WWDC 中的流体界面原则转成 Web 交互约束，但本身不是 Apple 官方 Skill。
- 语义触发：拖拽、底部面板、手势、动量、弹簧、中途抓取/反向、动效机会筛选和严格动效审查。进入动画默认倾向 `ease-out`；手势驱动过渡从当前屏幕值继续，可打断、继承速度并支持 reduced motion。
- 不适用：为了视觉标签机械复刻 Apple 外观，或在密集数据界面中用动效牺牲阅读和操作速度。普通悬停和状态切换用 CSS 足够时，不引入复杂弹簧系统。
- 版本边界：视频当时说 6 个 Skill，当前官方 README 已扩展更多模块；调用前读取当前官方说明，不把视频数量固化为长期事实。
- 推荐组合：`apple-design` 负责流体交互原则，`animate` 负责具体动效实现，`review-animations` 负责显式动效审查；与 GSAP 的关系是“设计判断与质量门”配合“API、时间线、滚动和性能实现”。接收者必须在自己的环境中检查是否已安装；知识库不复制这些 Skill。
