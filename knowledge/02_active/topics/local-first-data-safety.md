# 本地优先、同步与防丢数

## 当前结论

本地优先不是“把数据存在浏览器”这么简单，而是一套完整协议：本地在离线时仍可工作；云端承担同步而不是替代本地；冲突、删除、迁移、版本和恢复都有明确语义。

## 推荐协议

1. 每条记录有稳定 ID 和更新时间，不用整包“最后写入者覆盖”。
2. 删除使用带时间戳的 tombstone，记录缺失本身不代表删除。
3. 本地空数据与云端做合并，禁止直接用空快照覆盖。
4. 写入前断言：没有明确删除标记时，关键记录数量不能意外减少。
5. 每次有效写入保存 before/after 快照；内容 fingerprint 未变化则跳过写入。
6. 数据协议升级先部署服务端，通过 capabilities 握手后客户端才允许写入。
7. 迁移只做增量变更；执行前备份，执行后用真实双设备或恢复流程验收。

## 产品语义

- “保存在本机”“已同步云端”“已生成备份”“已删除”是四种不同状态。
- 前端可见 key 不应被误当成数据库安全边界；真正边界来自用户隔离、RLS、最小授权和服务端校验。
- 云同步本身不等于端到端加密，敏感数据需单独评估。
