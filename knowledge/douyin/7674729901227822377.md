## AnyDoc 官方核验

- 官方仓库：<https://github.com/firecrawl/anydoc>；官方 Skill：<https://github.com/firecrawl/anydoc/blob/main/skills/convert-documents-to-markdown/SKILL.md>；MIT 许可。
- 官方支持 Word、PowerPoint、Excel、OpenDocument、RTF、EPUB、CSV 和文本型 PDF，统一输出 GitHub-Flavored Markdown，并提供 Rust、Node.js、Python、WASM 和 CLI 路线。
- 官方 Skill 的触发条件是：任务需要读取当前能力无法直接处理的办公文档、表格、演示文稿、电子书或 PDF 内容。大文档应先写入 `.md` 文件，再按需读取，避免把全部内容一次性塞进上下文。
- 限制：扫描或纯图片 PDF 不做 OCR；加密、损坏或超出安全限制的文件可能失败；转换成 Markdown 会丢失部分视觉布局、动画、原生图表语义或复杂对象，因此不能替代原格式的版面验收。
- “纯本地”只适用于本地库/CLI 路线；若使用托管 Firecrawl Parse 处理 OCR，就不再是纯本地。`npx` 首次运行仍会下载预编译包，不能理解为零依赖、零网络。
- 适用：把多格式资料规范化后用于全文检索、RAG、知识库、内容抽取或 Agent 上下文；尤其适合文本结构比视觉版式更重要的批量文档。
- 不适用：扫描件 OCR、要求像素级还原、需要保留 PPT 动画/Excel 公式执行/原生图表编辑，或敏感文档不能接受首次下载依赖而又未完成供应链审查的环境。
- 当前状态：用户已明确授权，官方 `convert-documents-to-markdown` Agent Skill 于 2026-08-19 安装完成，下一轮任务起可触发。AnyDoc CLI 本体将在首次实际转换时按 Skill 说明获取；本次没有转换用户文档。
