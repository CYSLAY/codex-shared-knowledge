# 三个前端 Skill：审查、设计与截图实现

## 核心摘要

视频用 16 秒区分三个前端任务：`web-design-guidelines` 用于审查现有界面，`design-taste-frontend` 用于提升新页面或重设计的视觉判断，`image-to-code` 用于把明确的截图或设计稿实现为可交互前端。它们不能互相替代，应按任务阶段路由。

## 完整内容时间轴

- `00:00–00:06`：`web-design-guidelines` 审查网页字体、间距、按钮、交互与不舒服之处。
- `00:06–00:12`：`design-taste-frontend` 提高 Codex 的设计标准，减少模板化的“AI 味”。
- `00:12–00:16`：`image-to-code` 从网站截图提取布局并生成前端页面，用于复刻布局和交互。

## 官方资料核验与路由

### web-design-guidelines

- 官方来源：Vercel `vercel-labs/agent-skills` 中的 `web-design-guidelines/SKILL.md`。
- 能力：每次拉取最新 Web Interface Guidelines，审查指定文件并以 `file:line` 形式输出问题。
- 何时用：已有 UI 代码，需要做一致性、可访问性、交互与上线前审查。
- 何时不用：尚未确定设计方向、需要从零构思视觉语言，或没有可审查的代码文件。
- 来源环境状态：技能列表中未安装；接收者应检查自身环境。

### design-taste-frontend

- 官方来源：`Leonxlnx/taste-skill`；来源环境已安装同名 Skill，接收者仍需检查自身环境。
- 能力边界：适用于落地页、作品集和重设计，先推断页面类型、受众与设计语言，再设置变化度、动效强度和视觉密度；官方明确不以仪表盘、数据表格或多步骤产品 UI 为主。
- 何时用：用户要求高审美营销页、作品集、品牌页或重设计，且当前任务确实命中其范围。
- 何时不用：复杂后台、密集数据产品或仅修逻辑 Bug。
- 来源环境状态：可调用；接收者实际任务命中时必须先读取当前机器上的 `SKILL.md`。

### image-to-code

- 官方来源：OpenAI `role-specific-plugins` 的 Product Design 插件中 `image-to-code/SKILL.md`。
- 能力：把用户明确选定的截图、设计稿或图像参考实现为响应式、可交互前端，并以浏览器和设计 QA 做验收。
- 何时用：存在唯一、明确的视觉目标，任务要求忠实实现而不是自由设计。
- 何时不用：只有文字需求、目标图不明确、用户希望重新设计而不是复刻，或无法完成浏览器视觉验收。
- 来源环境状态：没有该独立 Skill，也没有对应 Product Design 插件。接收者应检查自身环境；未安装时可应用“明确目标—测量—实现—截图 QA”的方法，但不能声称调用。
